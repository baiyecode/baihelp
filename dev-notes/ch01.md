**翻车与返工：Context7 MCP 报 Invalid API key**

- 现象：`resolve-library-id` / `query-docs` 全部报 "Invalid API key. API keys should start with 'ctx7sk' prefix."
- 诊断：插件 `.mcp.json` 写死 `Authorization: ${CONTEXT7_API_KEY:-}`，环境变量未设置时 ZCode 客户端不展开 `:-` 默认值语法，把**字面量**当密钥发出；用 curl 直连 `mcp.context7.com` 匿名完整握手 + 工具调用全部正常，证明服务端无问题
- 修复：已移除插件缓存中该请求头（匿名模式，官方声明开箱可用）；MCP 连接在会话启动时建立，**本会话内仍以 curl 直连方式使用 Context7**，下个会话起 MCP 工具应原生恢复

**Context7 查证结论（写码前已核对的 API 事实）：**

1. FastAPI 现有**原生 SSE 模块** `fastapi.sse`：`EventSourceResponse` + `ServerSentEvent(data=..., event=...)`，POST 端点可用（`response_class=EventSourceResponse`）——旧记忆中的手工 StreamingResponse 拼 `data:` 写法已过时
2. LangChain 结构化输出：`model.with_structured_output(PydanticModel, include_raw=True)`，Pydantic Field description 参与提示；另有 `method="json_schema"`
3. OpenAI 兼容第三方接入：官方推荐 `init_chat_model(model=..., model_provider="openai", base_url=..., api_key=...)`，正是 .env 换接四家所需的形态
4. 流式：`astream()` 逐个 yield `AIMessageChunk`，`chunk + chunk` 聚合为完整消息；`astream_events()` 是事件级方案（ch01 用简单 `astream()` 即可）
5. 历史裁剪：新文档的裁剪方案绑定了 agent 中间件（`SummarizationMiddleware`/`@before_model`，需要 create_agent/LangGraph）——本章不做 Agent，**改用手写 token 预算裁剪原语**（可单测，恰好符合 TDD 要求）
