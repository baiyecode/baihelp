## 阶段 0 · Kickoff 与分类（2026-09-27）

**用户关键原话：**

> "我要用 Superpowers 模式给现有的客服系统装上查数据的能力,用 Function Calling 让模型自己决定调什么工具——工具链要长在客服聊天本身,用户在聊天页问一句就能触发。"
> "query_order 查订单、query_product 查商品、query_logistics 查物流:这三个真实场景该调公司电商系统和物流系统的 API,演示起见在工具内部随机生成数据返回,不接真实接口、不建表"
> "只做单轮调用:模型调一次工具就收敛"
> "聊天页改造是例外,用 Vibe Coding 方式直接做,我描述效果你改,不套 brainstorm、TDD、code review 那套流程"
> "选第一个，然后这是表语句在这里：J:\code\SQL\ch02-ddl.sql    记得建表" —— 模型上下文读取路径选写穿式,建表以用户 DDL 为准
> "Subagent-driven(推荐)" —— 执行方式与 ch01 一致

**关键产出：**

- 分类判断：**Architectural 路径**（新子系统：DB 层 + 工具链 + 聊天链路改造），走完整流程
- Context7 查证（写码前已核对的 API 事实）：
  1. LangChain `@tool(args_schema=Pydantic模型)` 定义工具；`model.bind_tools([...])` 绑定
  2. 流式工具调用：`astream()` 产出含 `tool_call_chunks` 的 `AIMessageChunk`，chunk 逐个相加聚合得完整 `tool_calls`
  3. `tool.invoke(tool_call)` 直接返回带 `tool_call_id` 的 `ToolMessage`；手工回灌 = 消息列表追加 ToolMessage 再喂给模型
  4. SQLAlchemy 2.0 异步：`create_async_engine("mysql+aiomysql://...")` + `async_sessionmaker` + `conn.run_sync(Base.metadata.create_all)`；测试可用 `sqlite+aiosqlite` 内存库
- 设计取舍（AskUserQuestion 确认）：历史读取=**写穿式**（消息实时落 MySQL，模型上下文仍读内存 SessionStore）；执行=**Subagent-driven**
- 用户 DDL 关键约束吸收：conversations 无 session_id 列（以 user_id 承接浏览器 session_id，一个聊天窗口=一通会话）；中文 ENUM 原样保留；工单号格式 `T+YYYYMMDD+3位序号`；messages.content 允许空（纯工具调用帧）；DDL 原样进仓库经 docker-entrypoint-initdb.d 自动建表
- 设计方案经计划审批（ExitPlanMode）通过：两段式单轮收敛（第一段绑工具流式、聚合出 tool_calls 则推状态帧+执行+回灌、第二段裸模型流式最终回答）、工具基础设施（注册/校验/超时重试/错误捕获）、评估集替代 TDD 验证工具选型行为
- 建分支 `ch02/function-calling`（base `9271ea0`），建立本留痕文件
